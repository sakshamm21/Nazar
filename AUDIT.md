# StockAI v1 audit (input to Nazar v2.0)

> Audit of StockAI v1 as of October 2026, kept for reference. What was built from it: [PLAN.md](PLAN.md) (with an "as built" note), [FEATURES.md](FEATURES.md) and [DECISIONS.md](DECISIONS.md).

*Audited 3 Oct 2026 at commit `2626a3d`. Method: read every source file (≈6,600 lines), ran typecheck and lint, ran the app locally against an isolated PGlite database, exercised every API feature over HTTP (sign-in, watchlist, price alerts, alert check, cron auth, events, chat in English, Hinglish and off-topic, feedback, share links, /insights), and stress-tested Yahoo Finance with the Nifty 50.*

**Verdict:** the research engine is strong and worth keeping almost entirely: the 22 tools, 7 quant models, 43-metric catalog, Excel models, guard, limits and analytics. What has to change is everything around it. v1 is a chat product with no portfolio, no outbound channel, live Yahoo calls on page views, and an identity model that is not safe for financial data.

Legend: **KEEP** = reuse as is · **IMPROVE** = reuse with changes · **MOVE** = reuse, but in a different place in the product · **CUT** = remove in v2.0

## 2. Bugs and fragile code

| #    | Severity       | Finding                                                                                                                                                                                                                                                                                               | Evidence                                                                                       |
| ---- | -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| B-1  | **High** | Fingerprint login accepts any client-supplied hash. Anyone who can produce or guess another device's fingerprint, or simply owns an identical device, gets that account.                                                                                                                              | Signed in with`"a"×64` and `"b"×64` locally. `auth.ts:121-136` only checks the format. |
| B-2  | High           | The analysis models call Yahoo**with no cache and no retry**: `closes()` and `annualFundamentals()` call `yf.chart` / `yf.fundamentalsTimeSeries` directly. A comps run or a correlation matrix fans out 2–9 uncached calls.                                                           | `analysis-tools.ts:56,76` (v.s. `finance.ts` `cached()`)                                 |
| B-3  | High           | Yahoo is hit per page view and per user: watchlist load, alert check on app load, 60s polling while alerts are active, and`createAlert` / `addToWatchlist` validation.                                                                                                                            | `watchlist.ts:14`, `App.tsx:161-180`, `alerts.ts`                                        |
| B-4  | Medium         | `withRetry` retries once after 0.7–1.2s with no exponential backoff, no `Retry-After` handling and no global concurrency cap. Ten parallel tool calls can each hit a 429 and retry at the same moment.                                                                                           | `finance.ts:19`                                                                              |
| B-5  | Medium         | Two sources of truth for the schema:`schema.ts` (Drizzle) and the hand-written `BOOTSTRAP_SQL`. They already disagree (`usage_created_idx` exists only in SQL), and `drizzle.config.ts` points to a migrations folder that doesn't exist.                                                     | `db/schema.ts`, `db/index.ts:26`                                                           |
| B-6  | Medium         | On Neon, the ~40-statement bootstrap runs as one transaction on**every cold start**, adding latency to the first request of every new instance.                                                                                                                                                 | `db/index.ts:26-27`                                                                          |
| B-7  | Medium         | Yahoo's`beta` metric is wrong for NSE stocks: Infosys 0.11, TCS 0.17, HDFC Bank 0.40 (realistic values are roughly 0.6–1.0 vs Nifty). Any feature that reads `summaryDetail.beta` would understate risk badly.                                                                                   | Live check, 3 Oct 2026                                                                         |
| B-8  | Medium         | Piotroski/Altman are computed and returned for banks and NBFCs with only a note saying they're "not meaningful". A value-weighted portfolio health score would silently include meaningless numbers for typically 25–40% of an Indian portfolio.                                                     | `analysis-tools.ts:322`                                                                      |
| B-9  | Low            | The in-memory cache is per serverless instance with crude FIFO eviction, so on Vercel it rarely hits. | B-10 | Low            | A dev fallback secret is used when`NEXTAUTH_SECRET` is missing outside production, and fingerprint hashes and IP hashes are salted with it. That's fine locally, but there's no startup check in preview builds.                                                                                    | `auth.ts:16`                                                                                 |
| B-11 | Low            | `NEXTAUTH_URL` warning on every request in dev. Harmless noise.                                                                                                                                                                                                                                     | dev log                                                                                        |
| B-12 | Low            | `.env.local` begins with a UTF-8 BOM, written by `deploy.ps1`'s `Set-Content`. Harmless today because the first line is a comment, but a variable on line 1 would be misread.                                                                                                                   | file bytes                                                                                     |

## 3. Data reliability findings (Yahoo Finance)

### 3.1 Stress test: Nifty 50, every call the nightly batch would make

Run from a residential Indian IP, 3 Oct 2026 (market closed; last session 1 Oct, because 2 Oct was a holiday).

| Call                              | Mode                       | Result  | p50 / p95 latency        | Wall time            |
| --------------------------------- | -------------------------- | ------- | ------------------------ | -------------------- |
| `quote` ×50 symbols            | **one batched call** | 50/50   | —                       | **0.8s**       |
| `chart` 400d daily              | sequential                 | 50/50   | 153 / 239 ms             | ~9s                  |
| `quoteSummary` (7 modules)      | sequential                 | 50/50   | 102 / 276 ms             | ~7s                  |
| `fundamentalsTimeSeries` annual | sequential                 | 50/50   | 484 / 625 ms             | ~25s                 |
| the same three                    | concurrency 10             | 150/150 | 336–1057 / 493–1305 ms | **~10s total** |
| `search` (names)                | sequential                 | 10/10   | 308 / 565 ms             | 3s                   |

**450 calls, zero errors, no 429s.**

**Cloud-IP follow-up (step 0 of the build).** The same test, run three times back to back from a temporary Vercel function in `bom1` (Mumbai): **750 calls, zero errors, no 429s**. The full 50-symbol set (batch quote + chart + quoteSummary + annual fundamentals at concurrency 4) took **~10s per run**, and Google News RSS answered 200. The temporary project was deleted afterwards. Vercel Cron is therefore the nightly runner, and the GitHub Actions fallback stays unused. Implication: one nightly run for a few hundred unique symbols needs about 1–3 minutes of Yahoo time at modest concurrency, which fits a 300s function only if the work is chunked and resumable.

| Banks / NBFCs health                   | Statement fields are often missing, and Piotroski/Altman don't apply.                                                                                                                                                                                                                                    | Use a separate, clearly labelled "lender check" (PLAN.md §5.3).                                                                                                                                                                       |
| Sectors                                | `assetProfile` sectors are US-style ("Financial Services / Banks - Regional").                                                                                                                                                                                                                         | Good enough for allocation. Map them to Indian-friendly labels.                                                                                                                                                                        |

## 5. Risks spotted for v2

- **R-1:** `.vercel/project.json` in this folder is linked to the **v1** project `stockai`. Running `vercel --prod` from the v2 branch would overwrite v1. Phase 3 must re-link to a new `nazar` project first.
- **R-2:** Yahoo may block or rate-limit Vercel's IPs. That's untested (§3.1). Mitigations are in PLAN.md.
- **R-3:** Broker export formats change without notice, and I have no real Groww or Upstox samples (PLAN.md Q5).
